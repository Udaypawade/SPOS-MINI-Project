📚 SafeCare Conceptual Reference

Core Operating System concepts, Banker's algorithm mathematical rules, and deadlock avoidance principles.

1

What is Dijkstra's Banker's Algorithm?

The Banker's Algorithm is a classic deadlock avoidance algorithm developed by Edsger Dijkstra. It is modeled after a banker who never allocates cash exceeding the available pool in a way that prevents satisfying the maximum needs of every client.

In SafeCare, it ensures that hospital ICU critical care resources (Beds, Ventilators, Oxygen, Monitors) are never granted to patients if doing so leaves the hospital in an Unsafe State where a deadlock could occur.

2

Safe State vs Unsafe State

Safe State: A state is safe if there exists at least one Safe Sequence $\langle P_1, P_2, \dots, P_n \rangle$ such that for every $P_i$, the resources that $P_i$ still needs can be satisfied by current Available plus resources currently held by all preceding processes $P_j$ ($j < i$).

Unsafe State: No safe sequence exists. An unsafe state is not necessarily a deadlock, but it is a state that may lead to deadlock if processes request their maximum claims.

3

The Four Coffman Conditions

  • 1. Mutual Exclusion: Resources are held in non-shareable mode.
  • 2. Hold and Wait: Processes hold resources while waiting for more.
  • 3. No Preemption: Resources cannot be forcibly revoked.
  • 4. Circular Wait: A closed chain of processes each waiting for resources held by the next.

SafeCare uses Deadlock Avoidance, which dynamically checks resource requests to ensure Circular Wait can never materialize.

4

Resource-Request Algorithm Steps

  1. Condition 1: $Request_i \le Need_i$ (Cannot exceed remaining need).
  2. Condition 2: $Request_i \le Available$ (Cannot exceed available pool).
  3. Tentative Allocation: Temporarily grant $Allocation = Allocation + Request$ and $Available = Available - Request$.
  4. Safety Check: Run Safety Algorithm. If safe, finalize. If unsafe, rollback to prior state.
